Every chart, dasha, and transit starts from planetary positions, and those come
from one place: the **ephemeris**. Pick the layer that provides it, tune its
position cache, or write your own adapter for tests or another position source.

## Ephemeris service

`Ephemeris.Ephemeris` is an Effect service with three operations. Charts consume
it; adapters implement it.

| Operation | What it does |
| --- | --- |
| `dateToJulianDay(date)` | Converts a UTC `DateTime` to a Julian Day. |
| `calculatePosition(julianDay, planet, ayanamsa)` | Returns the sidereal position of one graha. Takes any of the nine, Rahu and Ketu included. |
| `calculateHouses(julianDay, latitude, longitude, houseSystem, ayanamsa)` | Returns twelve sidereal house cusps keyed 1 to 12, and the chart angles. |

All three fail with a typed `EphemerisError`. The interface speaks in domain
terms: an adapter hides its native bodies, node conventions, cusp layout, and
tropical offset, and hands back sidereal longitudes.

## Layers

| Layer | What it gives you |
| --- | --- |
| `Swisseph.SwissephLayer` | The Swiss Ephemeris adapter. Every position lookup calls the native library. |
| `Swisseph.SwissephCachedLayer` | The same adapter with a position cache in front. Use it for transits and anything repeated. |
| `Runtime.MainLayer` | The default AstroParams plus the cached Swiss Ephemeris layer. The Quickstart uses it. |
| `Ephemeris.withPositionCache(options)` | A decorator that adds the cache to any ephemeris layer, yours included. |

By default, use `Runtime.MainLayer`. It already includes the cached layer.

## Position cache

The cache wraps `calculatePosition` only and keys each result by Julian Day,
planet, and ayanamsa. The same positions are requested over and over:

- A single chart makes nine position calls, one per graha, plus one houses call.
- A transit search looks up the same graha repeatedly as it scans ahead and
  refines each crossing to the minute.
- A dashboard that redraws the same moment asks for the same positions again.

Behavior:

- **Hits skip the native call.** A second chart for the same moment makes no
  new position calls.
- **Concurrent identical lookups share one call.** If two requests ask for the
  same position at once, only one runs.
- **Failures are never cached.** A transient native error stays retryable.
- **Only positions are cached.** Houses and Julian Day conversion run once per
  chart and gain nothing from caching.
- **Defaults are 10,000 entries and a 10-minute lifetime.**

See the [stress benchmark
notes](https://github.com/astro-ascendant/ascendant-ts/blob/main/benchmarks/stress.md)
for measured speedups on a warm cache.

<Callout type="info" title="Create the runtime once">
  The cache lives inside the layer. A `ManagedRuntime` builds its layers once
  and keeps them, so one long-lived runtime shares one cache across all
  requests. Each additional runtime builds its own layer with its own empty
  cache. That is why the Quickstart creates the runtime once and reuses it.
</Callout>

### Tune the cache

Wrap the plain layer yourself to change the capacity or the lifetime.

```ts
import { AstroParams, Chart, Ephemeris, Swisseph } from "astro-ascendant";
import { Layer, ManagedRuntime } from "effect";

const tuned = Ephemeris.withPositionCache({
  capacity: 50_000,
  timeToLive: "1 hour",
}).pipe(Layer.provide(Swisseph.SwissephLayer));

const runtime = ManagedRuntime.make(
  Layer.mergeAll(AstroParams.DefaultAstroParams, tuned),
);
```

Raise the capacity for services that scan many moments, such as wide transit
windows. Shorten the lifetime if memory matters more than speed. Positions for
a given moment never change, so the lifetime only bounds memory use.

To keep the default settings and change only the ephemeris, reuse the
runtime's settings layer:

```ts
import { Runtime } from "astro-ascendant";

const layer = Layer.mergeAll(Runtime.AstroParamsSubgraph, tuned);
```

`Runtime.AstroParamsSubgraph` is the AstroParams half of `MainLayer`, and
`Runtime.EphemerisSubgraph` is the ephemeris half.

## Swiss Ephemeris adapter

The built-in adapter wraps the native `@swisseph/node` package and does the
conversion work for the rest of the library:

- Decodes every native result into validated schemas, so corrupt output fails
  with a typed `EphemerisError` and does not spread
- Reads Rahu from the mean lunar node and places Ketu opposite it
- Turns the native thirteen-slot cusp array into twelve sidereal cusps keyed by
  house
- Applies the `WholeSign` convention itself

## Write your own adapter

Provide your own `Ephemeris` for unit tests, another position source, or an
environment without the native library. An adapter is a `Layer` that
implements the three operations.

This one reports fixed longitudes, which makes charts exact and repeatable in
tests:

```ts
import { AstroParams, Chart, Ephemeris } from "astro-ascendant";
import { DateTime, Effect, Layer, ManagedRuntime } from "effect";

const LONGITUDES: Record<Chart.Planets, number> = {
  Sun: 256.6, Moon: 199.5, Mars: 304.2, Mercury: 244.1, Jupiter: 25.7,
  Venus: 285.3, Saturn: 41.9, Rahu: 69.3, Ketu: 249.3,
};

const fixedEphemeris = Layer.succeed(
  Ephemeris.Ephemeris,
  Ephemeris.Ephemeris.of({
    dateToJulianDay: (date) =>
      Ephemeris.JulianDay.makeEffect(Ephemeris.julianDayOfDateTime(date)).pipe(
        Effect.mapError((cause) =>
          Ephemeris.EphemerisError.make({ operation: "dateToJulianDay", cause }),
        ),
      ),
    calculatePosition: (_julianDay, planet) =>
      Effect.succeed({
        longitude: Chart.Longitude.make(LONGITUDES[planet]),
        latitude: 0,
        distance: 1,
        longitudeSpeed: 1,
        latitudeSpeed: 0,
        distanceSpeed: 0,
      }),
    calculateHouses: (_julianDay, _latitude, _longitude, houseSystem) =>
      Effect.succeed({
        houseSystem,
        cusps: Object.fromEntries(
          Chart.Houses.literals.map((house) => [
            house,
            Chart.Longitude.make(((house - 1) * 30 + 69.6) % 360),
          ]),
        ) as Record<Chart.Houses, Chart.Longitude>,
        angles: {
          ascendant: Chart.CircleAngle.make(69.6),
          mc: Chart.CircleAngle.make(339.6),
          armc: Chart.CircleAngle.make(339.6),
          vertex: Chart.CircleAngle.make(159.6),
          equatorialAscendant: Chart.CircleAngle.make(0),
          coAscendant1: Chart.CircleAngle.make(0),
          coAscendant2: Chart.CircleAngle.make(0),
          polarAscendant: Chart.CircleAngle.make(0),
        },
      }),
  }),
);

const runtime = ManagedRuntime.make(
  Layer.mergeAll(AstroParams.DefaultAstroParams, fixedEphemeris),
);

const located = Chart.LocatedMoment.make({
  moment: Chart.Moment.make({ date: DateTime.makeUnsafe("2000-01-01T12:00:00Z") }),
  latitude: 12.9716,
  longitude: 77.5946,
});

const calculation = await runtime.runPromise(Chart.generate(located));
calculation.charts[0].houses[1].sign; // "Gemini"
```

Nothing else changes. `Chart.generate`, the dashas, and the other calculations
use whichever `Ephemeris` you provide.

### Adapter requirements

- **Return sidereal longitudes.** Apply the `ayanamsa` argument yourself. The
  rest of the library treats every longitude as sidereal.
- **Handle all nine grahas.** Rahu and Ketu are positions like any other, so
  your adapter decides how to place them.
- **Return twelve cusps keyed 1 to 12 and the full set of chart angles.** Honor
  the `houseSystem` argument, including `WholeSign`.
- **Report real speeds for transit searches.** Stations are found where
  `longitudeSpeed` changes sign, so a constant speed gives no stations. The
  fixed adapter above works for charts, not for station searches.
- **Fail with `EphemerisError`.** Set `operation` to the name of the failed
  call and put the underlying reason in `cause`. See [Errors and typed
  failures](/docs/guides/errors).

### Cache your adapter

Wrap your adapter in the same decorator.

```ts
const cachedFixed = Ephemeris.withPositionCache({ capacity: 1_000, timeToLive: "1 hour" }).pipe(
  Layer.provide(fixedEphemeris),
);
```

With this layer, the first chart for a moment makes nine position calls to
your adapter, and a second chart for the same moment makes none.

## Choose a layer

| You are | Provide |
| --- | --- |
| Following the Quickstart, or building a typical app | `Runtime.MainLayer` |
| Running transit searches or serving repeated moments | `Swisseph.SwissephCachedLayer`, in one long-lived runtime |
| Debugging the native adapter, or wanting no state | `Swisseph.SwissephLayer` |
| Needing a different capacity or lifetime | `Ephemeris.withPositionCache(...)` over `Swisseph.SwissephLayer` |
| Writing tests, or using another source of positions | Your own `Ephemeris` layer, optionally wrapped in `withPositionCache` |

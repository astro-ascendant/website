---
title: Dashas
description: Calculate Vimshottari, Chara, and Sthira dasha timelines, split Vimshottari to Sookshma, and query the period active on any date.
---

A **dasha** is a timeline of periods. Each period has a lord, a start, and an
end, and each Mahadasha divides into Antardashas. Ascendant calculates three
systems from the **Placements** that `Chart.generate` returns:

| System | Periods are ruled by | Mahadashas | Antardashas in each | School |
| --- | --- | --- | --- | --- |
| **Vimshottari** | Planets, in a fixed cycle | 9 | 9 | Used with both KP and Parashari |
| **Chara** | Signs | 12 | 12 | Jaimini |
| **Sthira** | Signs | 12 | 12 | Jaimini |

Vimshottari goes two levels deeper: each Antardasha splits into nine
**Pratyantardashas**, and each of those into nine **Sookshma** dashas.

## Placements

Every dasha function takes the birth **Moment** and the **Placements**.
Calculate the placements once and reuse them.

```ts
import { Chart, Dasha, Runtime } from "astro-ascendant";
import { DateTime, ManagedRuntime } from "effect";

const runtime = ManagedRuntime.make(Runtime.MainLayer);

const located = Chart.LocatedMoment.make({
  moment: Chart.Moment.make({ date: DateTime.makeUnsafe("2000-01-01T12:00:00Z") }),
  latitude: 12.9716,
  longitude: 77.5946,
});

const { placements } = await runtime.runPromise(Chart.generate(located));
```

The dasha is anchored to the birth moment. Pass the same `located.moment` you
used for the chart.

## Vimshottari

`Dasha.calculate` builds the Vimshottari timeline from the Moon's star and the
portion of that star's period left at birth.

```ts
const timeline = await runtime.runPromise(
  Dasha.calculate(located.moment, placements),
);
```

The result is an array of nine Mahadashas covering the full 120-year cycle.
Each has a `mahadasha` lord, a `start`, an `end`, and nine `antardashas`.

```ts
const day = (date: DateTime.Utc) => DateTime.formatIso(date).slice(0, 10);

for (const period of timeline) {
  console.log(`${period.mahadasha}: ${day(period.start)} to ${day(period.end)}`);
}
```

For the birth above:

| Mahadasha | Start | End |
| --- | --- | --- |
| Rahu | `1982-08-12` | `2000-08-12` |
| Jupiter | `2000-08-12` | `2016-08-12` |
| Saturn | `2016-08-12` | `2035-08-12` |
| Mercury | `2035-08-12` | `2052-08-12` |
| Ketu | `2052-08-12` | `2059-08-12` |
| Venus | `2059-08-12` | `2079-08-12` |
| Sun | `2079-08-12` | `2085-08-12` |
| Moon | `2085-08-12` | `2095-08-12` |
| Mars | `2095-08-12` | `2102-08-12` |

<Callout type="info" title="The first period starts before birth">
  The birth falls part-way through the period of the Moon's star lord, so the
  first Mahadasha begins before it, here in 1982. The timeline shows the whole
  Rahu period. Use the query below to find what is running on a given date.
</Callout>

Each Mahadasha holds its own Antardashas. The first three of the Rahu Mahadasha
are Rahu to `1985-04-24`, Jupiter to `1987-09-18`, and Saturn to `1990-07-24`.

```ts
const first = timeline[0];
for (const sub of first.antardashas) {
  console.log(`${sub.mahadasha}-${sub.antardasha}: ${day(sub.start)} to ${day(sub.end)}`);
}
```

### Pratyantardasha and Sookshma

The timeline stops at Antardashas because the deeper levels multiply fast: 729
Pratyantardashas and 6,561 Sookshmas across 120 years. Split a period only when
you need it.

- `Dasha.pratyantardashas`: takes an Antardasha, returns its nine
  Pratyantardashas
- `Dasha.sookshmas`: takes a Pratyantardasha, returns its nine Sookshmas

Both are plain functions, not effects, so they need no runtime.

```ts
const saturn = timeline[2];
const sun = saturn.antardashas.find((sub) => sub.antardasha === "Sun")!;

const pratyantardashas = Dasha.pratyantardashas(sun);
for (const period of pratyantardashas) {
  console.log(`${period.pratyantardasha}: ${day(period.start)} to ${day(period.end)}`);
}

const sookshmas = Dasha.sookshmas(pratyantardashas[0]);
```

Each level starts from its parent's lord, follows the Vimshottari order, and
gives each lord the same share of its parent that the lord takes of the
120-year cycle. For the Saturn Mahadasha's Sun Antardasha:

| Pratyantardasha | Start | End |
| --- | --- | --- |
| Sun | `2026-08-02` | `2026-08-19` |
| Moon | `2026-08-19` | `2026-09-17` |
| Mars | `2026-09-17` | `2026-10-08` |
| Rahu | `2026-10-08` | `2026-11-29` |
| Jupiter | `2026-11-29` | `2027-01-14` |
| Saturn | `2027-01-14` | `2027-03-10` |
| Mercury | `2027-03-10` | `2027-04-28` |
| Ketu | `2027-04-28` | `2027-05-18` |
| Venus | `2027-05-18` | `2027-07-15` |

The first Sookshma of the Sun Pratyantardasha runs from `2026-08-02T12:48Z` to
`2026-08-03T09:37Z`, under a day. Sookshma boundaries are rounded to the
minute. The last child always ends exactly where its parent ends, so the levels
line up with no gaps.

KP practice calls the third level **Antara**. It is the same period:
`PratyantarDasha` in the API.

### Find the running period

`Dasha.at` returns the chain active at a moment: the Mahadasha, Antardasha,
Pratyantardasha, and Sookshma. Pass no moment to use the current time.

```ts
const when = DateTime.makeUnsafe("2026-11-01T00:00:00Z");
const current = await runtime.runPromise(Dasha.at(timeline, when));

if (current) {
  console.log(current.mahadasha.mahadasha); // "Saturn"
  console.log(current.antardasha.antardasha); // "Sun"
  console.log(day(current.antardasha.start), day(current.antardasha.end));
  // 2026-08-02 2027-07-15
  console.log(current.pratyantardasha.pratyantardasha); // "Rahu"
  console.log(current.sookshma.sookshma); // "Mercury"
  console.log(day(current.sookshma.start), day(current.sookshma.end));
  // 2026-10-31 2026-11-07
}
```

Only the running branch is split, so the query stays cheap at any depth. Call
`Dasha.pratyantardashas` or `Dasha.sookshmas` yourself for any other period.

`Dasha.at` returns `null` when the date falls outside the timeline, for example
in 1900 or 2500. Always check before reading the result.

## Chara and Sthira

The Jaimini systems are sign-based. Call them with the same arguments.

```ts
const chara = await runtime.runPromise(
  Dasha.calculateChara(located.moment, placements),
);
const sthira = await runtime.runPromise(
  Dasha.calculateSthira(located.moment, placements),
);
```

Both return an object with a `system` tag, a `provenance`, and twelve
`mahadashas`, each with twelve `antardashas`. Their lords are signs, not
planets. For the birth above, both begin at the birth moment:

| System | First four Mahadashas |
| --- | --- |
| Chara | Gemini `2000-01-01` to `2006-01-01`, Taurus to `2012-01-01`, Aries to `2022-01-01`, Pisces to `2033-01-01` |
| Sthira | Libra `2000-01-01` to `2007-01-01`, Scorpio to `2015-01-01`, Sagittarius to `2024-01-01`, Capricorn to `2031-01-01` |

The `system` tag tells the two apart in your own types:

```ts
const describe = (dasha: Dasha.RashiDasha) =>
  dasha.system === "Sthira" ? `Brahma: ${dasha.brahma.planet} in ${dasha.brahma.sign}` : "Chara";
```

Sthira also returns the data behind its **Brahma** selection: the winning
planet and sign, the Atmakaraka used as the reference, the sign strengths of
the two candidate signs, and a score for each eligible planet. Here the Brahma
is the Moon in Libra. Show or log `sthira.brahma.selection` to explain the
choice.

Query either system with `Dasha.atRashi`.

```ts
const running = await runtime.runPromise(Dasha.atRashi(chara, when));

if (running) {
  console.log(running.system); // "Chara"
  console.log(running.mahadasha.mahadasha, running.antardasha.antardasha);
  // Pisces Virgo
}
```

For the same date, the Chara period is Pisces-Virgo, from `2026-08-01` to
`2027-07-01`, and the Sthira period is Capricorn-Taurus.

<Callout type="warn" title="Use the matching query">
  `Dasha.at` takes a Vimshottari timeline; `Dasha.atRashi` takes a Chara or
  Sthira one. Each result carries its own system's types, so TypeScript stops
  you mixing them. `Dasha.atRashi` goes to the Antardasha only: the
  Pratyantardasha and Sookshma levels are Vimshottari's.
</Callout>

## Date boundaries

The systems measure time differently, and it shows in the boundaries:

- **Vimshottari**: decimal years converted to calendar months, days, hours, and
  minutes. Boundaries fall at any time of day. In the example, Saturn begins at
  `12:48 UTC` on `2016-08-12`. Pratyantardashas and Sookshmas divide their
  parent's actual span, rounded to the minute.
- **Chara and Sthira**: whole calendar months. Boundaries fall on the first of
  a month, such as `2026-08-01`.

Treat the exact instants as part of the result. Do not round them to a day when
you compare periods across systems.

## Provenance

Every dasha records its method in `provenance`:

- Chara: Jaimini method `kn-rao-co-lord-strength`
- Sthira: Jaimini method `bv-raman-koch-brahma-strength`
- Vimshottari: Parashari method `moon-nakshatra-balance`, on each Mahadasha,
  since the timeline is a plain array

Each version is a date, currently `2026-11-01`. Store these with the timeline
if you show it later. See [Provenance and verification](/docs/guides/provenance).

## Errors

Dasha functions fail with typed errors:

- `DashaCalculationError`: a calculation cannot complete
- `DashaEvidenceError`: the placements do not hold exactly one entry for a
  required planet or the Lagna. This points to placements built or edited by
  hand instead of coming from `Chart.generate`.

See [Errors and typed failures](/docs/guides/errors).

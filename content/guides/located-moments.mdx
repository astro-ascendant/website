---
title: From local time to a Located Moment
description: Turn a birth date, local time, and place into the UTC moment and coordinates Ascendant calculates from.
---


Every calculation starts from a **Located Moment**: one UTC instant plus the
latitude and longitude where positions are calculated. Convert a local date,
clock time, and place to one safely, handle local times that are ambiguous or
do not exist, and pass valid coordinates.

## Input

A Located Moment has three fields:

| Field | Type | Rule |
| --- | --- | --- |
| `moment` | `Chart.Moment` | Wraps one UTC `DateTime`. |
| `latitude` | `number` | Decimal degrees, from -90 to 90. North is positive. |
| `longitude` | `number` | Decimal degrees, from -180 to 180. East is positive, so west is negative. |

Ascendant never reads a time zone. It works only in UTC, and the same Located
Moment always gives the same Placements. Converting local time to UTC is your
job, and it is where most mistakes happen.

## Build a Moment

Both common starting points use Effect's `DateTime`.

### From a timestamp with an offset

Parse an ISO 8601 string that carries an offset:

```ts
import { Chart } from "astro-ascendant";
import { DateTime, Option } from "effect";

const parsed = DateTime.make("2000-01-01T17:30:00+05:30");
// Option.some(2000-01-01T12:00:00.000Z)

const moment = Option.map(parsed, (date) => Chart.Moment.make({ date }));
```

`DateTime.make` returns an `Option`, because the string might be invalid. The
result is already UTC.

### From a local date, time, and time zone

Convert a wall-clock time and an IANA time zone name, such as `Asia/Kolkata`,
with `DateTime.makeZoned`:

```ts
const zoned = DateTime.makeZoned("2000-01-01T17:30:00", {
  timeZone: "Asia/Kolkata",
  adjustForTimeZone: true,
  disambiguation: "reject",
});

const utc = Option.map(zoned, DateTime.toUtc);
// Option.some(2000-01-01T12:00:00.000Z)
```

- `adjustForTimeZone: true`: reads the string as a wall-clock time in that
  zone. Without it, the string is read as UTC and only labeled with the zone.
- `disambiguation: "reject"`: returns `Option.none()` for times that are
  ambiguous or do not exist. See the next section.

### Ambiguous and nonexistent times

Clock changes create two kinds of bad local time:

| Case | Example in `America/New_York` | With `"reject"` |
| --- | --- | --- |
| A **gap**, when clocks jump forward, so the time never happened | `2021-03-14 02:30` | `Option.none()` |
| An **overlap**, when clocks fall back, so the time happened twice | `2021-11-07 01:30` | `Option.none()` |

The other modes (`"earlier"`, `"later"`, `"compatible"`) silently pick an
answer. That can move a birth by an hour and change the Lagna. For astrology,
prefer `"reject"`, then ask the user which moment they mean, or for the exact
UTC offset from their birth record.

### One conversion function

Put the conversion in one place so every input takes the same path:

```ts
import { Chart } from "astro-ascendant";
import { DateTime, Effect, Option } from "effect";

export const toLocatedMoment = (input: {
  readonly localDateTime: string; // "2000-01-01T17:30:00"
  readonly timeZone: string; // IANA name, e.g. "Asia/Kolkata"
  readonly latitude: number;
  readonly longitude: number;
}): Effect.Effect<Chart.LocatedMoment, string> =>
  Option.match(
    DateTime.makeZoned(input.localDateTime, {
      timeZone: input.timeZone,
      adjustForTimeZone: true,
      disambiguation: "reject",
    }),
    {
      onNone: () =>
        Effect.fail("That local time does not exist, or happens twice, in this time zone"),
      onSome: (zoned) =>
        Effect.succeed({
          moment: Chart.Moment.make({ date: DateTime.toUtc(zoned) }),
          latitude: input.latitude,
          longitude: input.longitude,
        }),
    },
  );
```

It fails with a message you can show the user, and succeeds with a value that
goes straight to `Chart.generate`:

```ts
const calculation = yield* toLocatedMoment(input).pipe(Effect.flatMap(Chart.generate));
```

## The place

A Located Moment also records where the birth happened.

### Time zone

Ascendant does not map coordinates to a time zone. The UTC offset depends on
both the place and the date: a place can change its offset over time, and
daylight saving rules differ by year. Look the zone up with a time zone lookup
package, or ask for it, and always combine it with the birth date.

<Callout type="warn" title="Historical births">
  `DateTime` uses the time zone data of its runtime. That data can be wrong or
  simplified for dates before the mid-twentieth century and for places that
  changed zones. If the birth record states the exact UTC offset, pass an ISO
  string with that offset instead of converting from a zone name.
</Callout>

### Coordinates

Give latitude and longitude in decimal degrees. Convert degrees, minutes, and
seconds first: `degrees + minutes / 60 + seconds / 3600`, negated for south and
west.

`Chart.generate` validates its input. An out-of-range value fails with a typed
`LocatedMomentValidationError`, so a bad latitude never produces a chart:

```ts
// latitude: 120 fails with:
// LocatedMomentValidationError:
//   Expected a value between -90 and 90 at ["latitude"]
```

`Chart.LocatedMoment.make` throws on the same input, because it validates
immediately. Pass a plain object, as the function above does, to get the
failure as an Effect error instead of an exception.

## Sex (optional)

`Chart.generate` also accepts `Chart.ChartParams`: a Located Moment with an
optional `sex` field. Ascendant copies it into each chart and uses it in no
calculation.

## Checklist

- Convert local time with the **birth date**, not today's date.
- Use `disambiguation: "reject"` and handle `Option.none()`.
- Longitudes west of Greenwich are negative.
- Pass the exact offset when you have it, especially for historical births.
- Keep the UTC moment and the original local input together if you show the
  result back to the user.

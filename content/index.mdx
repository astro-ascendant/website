Ascendant calculates sidereal (Vedic) astrology. It works out planetary
**Placements** once for a moment and place, then derives everything else from them:
charts, dasha timelines, Ashtakavarga, Jaimini results, and transit searches.

There are three ways to use it, depending on what you want to do.

## Start with a prompt

Copy this prompt into your coding agent (Claude Code, Codex, Cursor, Copilot,
Gemini CLI, or any other) and replace the last line with what you want to
build. It points the agent at these docs and sets the rules that keep
Ascendant code correct.

```text
I want to build an astrology feature in TypeScript with the astro-ascendant library (https://www.npmjs.com/package/astro-ascendant).

Before writing code:
1. Read https://astro-ascendant.vercel.app/llms.txt and open the pages relevant to my task. Use https://astro-ascendant.vercel.app/llms-full.txt if you need everything. Add .md to any docs page URL to get it as Markdown.
2. Take names and signatures from the API reference. Do not invent functions, options, or ayanamsa and house system names.

Rules:
- Install with `astro-ascendant` and `effect`. The library is Effect-based and every calculation returns an Effect.
- Create one ManagedRuntime from `Runtime.MainLayer`, reuse it for every call, and dispose it only at shutdown.
- All moments are UTC. Convert the birth's local date and time with its IANA time zone, which depends on the place and the date. If I haven't given a birth time, place, or time zone, ask me. Never guess them.
- Calculate Placements once with `Chart.generate` and reuse them for dashas, Ashtakavarga, Jaimini results, and transits.
- Defaults are the KrishnamurtiVP291 ayanamsa with Placidus houses (KP). Use Lahiri with WholeSign houses only for Parashari work, and never mix the two schools in one judgment. State the settings used.
- Only D1 has cusp-based houses and KP data. Divisional charts use whole-sign houses from their mapped Lagna.
- Handle failures through Effect's typed errors. Do not swallow them.
- The library calculates mechanics, not predictions. Do not present interpretations as certainty or as medical, legal, or financial advice.

Start with a short plan, then implement it. Verify the code compiles and runs.

My task: [describe what you want to build]
```

## Install the library

Ascendant is published on npm as `astro-ascendant`. It needs `effect` alongside it.

<Tabs items={["Bun", "Node"]} groupId="runtime" persist>
<Tab value="Bun">

```bash
bun add astro-ascendant effect
```

</Tab>
<Tab value="Node">

```bash
npm install astro-ascendant effect
```

</Tab>
</Tabs>

Then follow the [Quickstart](/docs/quickstart) to calculate your first chart and the
Vimshottari dasha running today.

## What the library calculates

| Calculation | What you get | Guide |
| --- | --- | --- |
| **Charts** | A cusp-aware D1 with KP evidence, and 15 whole-sign divisional charts. | [Divisional charts](/docs/guides/divisional-charts) |
| **Dashas** | Vimshottari planetary periods, and Jaimini Chara and Sthira sign periods, with date queries. | [Dashas](/docs/guides/dashas) |
| **Ashtakavarga** | Bhinnashtakavarga, Sarvashtakavarga, reduced tables, and Shodhya Pinda. | [Ashtakavarga](/docs/guides/ashtakavarga) |
| **Jaimini** | Chara Karakas, Rashi Drishti, Karakamsha, Arudha Pada, Upapada, and Argala. | [Jaimini calculations](/docs/guides/jaimini) |
| **Transits** | The next or previous sign ingresses, longitude hits, cusp crossings, and stations of a graha. | [Transit searches](/docs/guides/transits) |
| **Settings** | 47 ayanamsas and 13 house systems, recorded on every result. | [Choose a school and settings](/docs/guides/settings) |

By default Ascendant uses the sidereal zodiac, the KrishnamurtiVP291 ayanamsa, and
Placidus houses. Methods are named so you can check and repeat a result. A reading
is guidance, not certainty, and not a substitute for medical, legal, or financial
advice.
